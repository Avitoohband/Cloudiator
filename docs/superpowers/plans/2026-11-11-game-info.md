**Goal** Give players the approved Wiki and Future Updates tabs and let Avi edit both in-game and Codex edit the same drafts through MCP.

**Architecture** The static client opens Game Info from camp and reads published content. Private drafts live on the server. The owner and MCP editor use the same versioned writes, and only the owner publishes. The interface limits casual copying in the reader while leaving editing and navigation intact.

**Spec** [Idea 34](../specs/2026-10-29-next-patch-ideas.md), the approved clickable preview in parent `logs/game-info-preview-20261111/`, and the handoff decisions.

## Constraints

- Published content includes player guides, public patch plans and two YouTube links once supplied. Detailed formulas, drafts and internal patch plans stay outside the published content.
- Render authored content as text. Accept only approved YouTube HTTPS destinations. Keep keyboard and assistive technology access.
- Copy controls deter casual copying. A browser page cannot reliably prevent device screenshots. Keep information that requires confidentiality on the server.
- Require explicit approval for production steps. Use installed dependencies and the repository's migration and verification procedures.

## Authoring and publication design

- Store one versioned document per tab. Each document has ordered entries with a stable ID, a title and plain text. A Future Updates entry can carry an optional confirmed patch number. Wiki has two optional video URLs.
- Put published documents in a read-only public projection and drafts in a private table. Keep a private editor allowlist keyed by the verified account ID. The browser sends its existing Supabase session to an Edge function, which verifies identity and uses the backend-only database path for writes.
- Give MCP a dedicated credential that can read and save drafts in the same store. Validate the scope on the server. Keep publication available to Avi through the in-game editor. Every save and publish must compare the revision the editor opened, and a stale edit must leave both documents intact. Publish the checked draft and update its public revision in one transaction.
- Limit entry count and text size on the server. Render plain text and validate the two YouTube URLs before publication. Review the player view before publishing. Consider a visible Cloudiator attribution mark if redistribution becomes a problem.
- Review future changes for client data exposure. Keep unpublished plans, private operational data, credentials and authoritative decisions out of browser responses and bundles. Game code that must run in the browser is inspectable.
- Consider private edit history and rollback as more content is published. Audit which gameplay values must reach the browser before moving any other rules behind server responses.

### Service contract

- `POST /functions/v1/game-info` accepts `{action: "read", tab}` or `{action: "save", tab, expectedVersion, document}` for both authorized editors. The owner also uses `{action: "publish", tab, expectedVersion}`. `tab` is `wiki` or `future`. An authorized result is `{ok: true, version, document}`. Refusals use `{ok: false, code}` with `forbidden`, `conflict`, `invalid` or `unavailable`.
- `document` holds `entries` with `id`, `title`, `body` and an optional `patch` on Future Updates. Wiki holds two `videos` values, each a validated YouTube URL or null. Publish accepts the expected draft version and reads the draft inside the transaction.
- The local MCP process uses newline-delimited JSON-RPC over stdio and forwards only read and save requests. Its URL must be the Game Info HTTPS endpoint or a loopback test endpoint. It sends its own credential as a bearer token, and it rejects redirects so the credential cannot follow one.

### Configuration for release

- Enroll Avi's verified Google account in `private.game_info_editors` with separate production approval. The public Game Master title grants no editing rights.
- Set `CLOUDIATOR_GAME_INFO_MCP_TOKEN` for the Edge function through the existing secret workflow. Generate a dedicated random token with at least 32 bytes of entropy and encode it as base64url.
- Configure the Codex MCP process to run `node scripts/game-info-mcp.mjs` with the repository as its working directory or use the absolute script path. Supply `CLOUDIATOR_GAME_INFO_MCP_URL` and the same scoped token via the process environment. Keep the credential out of the repository and chat. The three tools are `game_info_list_tabs`, `game_info_read_draft` and `game_info_save_draft`.
