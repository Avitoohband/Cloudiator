# Patch A Implementation Plan: arrivals, watching an expedition, class bonuses, the phone bar, rest stamina, the clock and the players count

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Ship Avi's next-patch items 2-8 and the whole-trip expedition replay (game-messages Task 10) as a client-only
release, then a players' clip.

**Architecture:** Everything is in the static client (`src/`): pure modules for the words and the arithmetic (counts, the
clock formatter, the rest projection, the class split, arrivals, the trip planner, the camp vignettes), thin React and Phaser
layers over them, and three per-device localStorage keys behind try/catch. The only new reads are of data the client may
already read: the public `recent_results` projection (was the next slot a Rest?) and the owner's notifications read (the
"back" button's result). No migration, no Edge change, no new command.

**Tech Stack:** Next.js 16.4.3 static client, React, Phaser (lazy), Vitest, Playwright (`channel: 'chrome'`, private config).

**Spec:** `docs/superpowers/specs/2026-10-29-patch-a-design.md` (the approved mockup copy is quoted there word for word; the
mockup page itself, `.superpowers/design/2026-10-29-next-patch/mockups.html`, is local and ignored by git).

## Global Constraints

- Read the relevant guide in `node_modules/next/dist/docs/` before writing code (AGENTS.md); heed deprecation notices.
- No migration, no change under `supabase/`, no new command, no package download.
- Copy is the spec's, word for word (quotes, ellipses "…", arrows "→", "·" separators, "×", the emoji icons). Eyebrows are
  written in capitals in the source, as the existing panels do ("GUARDIAN BONUSES").
- Device keys, each read and written inside try/catch with an in-memory fallback for the page's life:
  `cloudiator.clock.v1` (`'12' | '24'`), `cloudiator.arrivals-seen.v1` (JSON array of ids, newest 200),
  `cloudiator.trip-closed.v1` (JSON array of activity ids, newest 50).

- Owner-only data (rewards, stamina) never reaches a visitor or another player's view.
- React async state (AGENTS.md): only the latest read lands; a slower earlier read never replaces a newer one; a flag that

- Gate of record: `node scripts/verify.mjs --config node_modules/.cache/pw-claude.config.mjs`.

- The plan:
  - Chapters: Leaving camp (5 s) · On the trail (departure → fight 1's start) · Fight N (its start → the next fight's start;

    `revealed: false`, and the chapters after it are placeholders too (no Resting).

    `stageWalks` plays at ×`TRIP_PACE.walk` for `walkMs(from, to)`; the rest of each stretch between fights (searching,
    waiting, resting at the safe point) shares what is left of the stretch's budget, `length / TRIP_PACE.travel`, in
    proportion to its display length, and zero when the walks use it up. Vignettes map to the departure (leaving) or to
    departure + 80 min (back, resting).
